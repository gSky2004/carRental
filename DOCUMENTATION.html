Car Rental Management System - Complete Documentation

This document explains the entire Car Rental Management System in detail. It covers the project structure, all 5 database tables, OOP concepts used, each file's purpose, and step-by-step instructions to run the system.

1. Project Overview

This is a Car Rental Management System built using the following technologies as required by the assignment:

Requirement Implementation
Frontend (User Interface) React 18 - A modern JavaScript framework for building user interfaces
Backend (Spring Boot) Spring Boot 3.2.5 with Java 17 - Provides REST API endpoints
Database PostgreSQL - Relational database for storing all data
Database Tables 5 tables: branches, customers, cars, rentals, payments
OOP Concepts Encapsulation, Inheritance, Classes, Objects, Constructors
CRUD Operations Full Create, Read, Update, Delete on all 5 entities

System Purpose: A car rental company can use this system to manage their fleet of cars, register customers, rent cars to customers, record payments, and manage branch locations. The system provides a clean web interface for all operations.

2. Database Design - 5 Tables with Relationships

The system uses five (5) database tables with the following relationships:

+----------------+ +----------------+ +----------------+ | branches | | cars | | customers | +----------------+ +----------------+ +----------------+ | id (PK) |<------| branch_id (FK) | | id (PK) | | name | | id (PK) | | first_name | | location | | car_name | | last_name | | address | | plate_number | | email | | phone | | brand | | phone | | created_at | | model | | license_number | | updated_at | | manufacture_yr | | address | +----------------+ | rental_price | | created_at | | status | | updated_at | | created_at | +----------------+ | updated_at | | +----------------+ | | | | 1 | 1 | | v v +------------------------------------+ | rentals | +------------------------------------+ | id (PK) | | car_id (FK) ------> cars.id | | customer_id (FK) > customers.id | | car_name (snapshot) | | plate_number (snapshot) | | customer_name (snapshot) | | customer_phone (snapshot) | | pickup_date | | return_date | | rental_days | | price_per_day | | total_cost | | created_at | +------------------------------------+ | | 1 | v +------------------------------------+ | payments | +------------------------------------+ | id (PK) | | rental_id (FK) --> rentals.id | | amount | | payment_date | | payment_method | | status | | created_at | | updated_at | +------------------------------------+

Table Relationships:

  1. Branch (1) to Car (N): One branch can have many cars parked at its location. A car belongs to one branch.
  2. Customer (1) to Rental (N): One customer can rent cars multiple times. Each rental belongs to one customer.
  3. Car (1) to Rental (N): One car can be rented many times over its lifetime. Each rental is for one car.
  4. Rental (1) to Payment (1): Each rental has exactly one payment record. This is a one-to-one relationship.

Table Details:

branches (Table 1)
Columns: id (PK), name, location, address, phone, created_at, updated_at
Purpose: Stores rental branch office locations. For example, "Main Branch" in Dar es Salaam and "Arusha Branch" in Arusha.
customers (Table 2)
Columns: id (PK), first_name, last_name, email, phone, license_number (unique), address, created_at, updated_at
Purpose: Stores customer information including their driver's license number for identification.
cars (Table 3)
Columns: id (PK), car_name, plate_number (unique), brand, model, manufacture_year, rental_price_per_day, status, branch_id (FK), created_at, updated_at
Purpose: Stores all cars available for rent. Status can be "Available", "Rented", or "Under Maintenance". Branch_id links to the branch where the car is located.
rentals (Table 4)
Columns: id (PK), car_id (FK), customer_id (FK), car_name, plate_number, customer_name, customer_phone, pickup_date, return_date, rental_days, price_per_day, total_cost, created_at
Purpose: Stores rental transactions. Note: car_name, plate_number, customer_name, customer_phone are "snapshots" - they are copied at the time of rental so the record stays accurate even if car or customer details change later.
payments (Table 5)
Columns: id (PK), rental_id (FK), amount, payment_date, payment_method, status, created_at, updated_at
Purpose: Stores payment records for each rental. Payment methods include CASH, CARD, and MOBILE (mobile money). Status can be PAID, PENDING, or REFUNDED.

3. Object-Oriented Programming (OOP) Concepts

The assignment requires demonstrating OOP concepts. Here is how each concept is implemented:

3.1 Encapsulation

Encapsulation means hiding internal data and only allowing access through public methods. In this project:

  • All entity classes have private fields (e.g., private String carName;).
  • Access to these fields is through public getter and setter methods (e.g., public String getCarName() and public void setCarName(String carName)).
  • Example from Car.java: The field status is private. To read it, you call getStatus(). To change it, you call setStatus("Rented").
  • DTO classes also use encapsulation - they hide the data and expose it through getters/setters.

3.2 Inheritance

Inheritance means a child class can reuse fields and methods from a parent class. In this project:

  • BaseEntity is an abstract parent class that contains common fields: id, createdAt, updatedAt.
  • Car, Customer, Branch, and Payment all extend BaseEntity using the extends keyword.
  • This means Car automatically has id, createdAt, and updatedAt without needing to define them again.
  • BaseEntity also has @PrePersist and @PreUpdate methods that automatically set the timestamps when records are created or modified.
// BaseEntity.java - PARENT CLASS @MappedSuperclass public abstract class BaseEntity { @Id @GeneratedValue(strategy = GenerationType.IDENTITY) private Long id; @Column(updatable = false) private LocalDateTime createdAt; private LocalDateTime updatedAt; // getters and setters for id, createdAt, updatedAt } // Car.java - CHILD CLASS inherits from BaseEntity @Entity @Table(name = "cars") public class Car extends BaseEntity { private String carName; private String plateNumber; // ... other Car-specific fields // Car gets id, createdAt, updatedAt FOR FREE from BaseEntity }

3.3 Classes and Objects

  • Classes: The project has entity classes (Car, Rental, Customer, Payment, Branch), DTO classes (CarDTO, RentalDTO, etc.), service classes, controller classes, and repository interfaces.
  • Objects: Objects are created using the new keyword, e.g., Car car = new Car(); or CarDTO dto = new CarDTO();. Objects are instances of classes.

3.4 Constructors

  • Every entity has a no-argument constructor (required by JPA): public Car() { }
  • Every entity has a parameterized constructor for easy object creation: public Car(String carName, String plateNumber, ...)

3.5 Methods

  • The project uses methods to organize code. For example, CarServiceImpl has methods like findAll(), findById(), save(), update(), delete(), convertToDTO(), and convertToEntity().
  • Controller methods handle HTTP requests: getAll(), getById(), create(), update(), delete().

3.6 Packages

The Java code is organized into packages following standard conventions:

  • com.oop.carrental - Main application package
  • com.oop.carrental.config - Configuration classes (CORS)
  • com.oop.carrental.controller - REST controllers

8. Detailed File Explanations

Below is every file in the project with a simple explanation of what it does.

BACKEND - Configuration & Entry Point

backend/pom.xml
Purpose: Maven configuration file that lists all Java libraries (dependencies) needed.
Dependencies: Spring Boot Web (REST API), Spring Data JPA (database access), PostgreSQL driver, H2 (for testing), Bean Validation.
backend/src/main/resources/application.properties
Purpose: Contains server and database settings.
Key settings: Server runs on port 8085. Database connects to PostgreSQL at localhost:5432/carrental_db. JPA automatically creates/updates tables (ddl-auto=update).
backend/src/main/java/com/oop/carrental/CarRentalApplication.java
Purpose: The main entry point. Contains the main() method that starts the Spring Boot server. Also has an initData() method that adds sample data (2 branches, 2 customers, 3 cars) when the application starts for the first time.
backend/src/main/java/com/oop/carrental/config/CorsConfig.java
Purpose: Configures CORS (Cross-Origin Resource Sharing) to allow the React frontend (running on port 3004) to make requests to the backend (running on port 8085). Without this, the browser would block the requests.

BACKEND - Entities (Database Tables)

entity/BaseEntity.java
OOP Concept: Inheritance (Parent Class)
This is an abstract class that provides common fields (id, createdAt, updatedAt) to all other entities. The @PrePersist and @PreUpdate annotations automatically set timestamps when records are created or modified.
entity/Car.java
Table: cars | Extends: BaseEntity
Represents a car in the rental fleet. Fields: carName, plateNumber (unique), brand, model, manufactureYear, rentalPricePerDay, status, branchId (FK to branches table).
entity/Customer.java
Table: customers | Extends: BaseEntity
Represents a customer who rents cars. Fields: firstName, lastName, email, phone, licenseNumber (unique), address.
entity/Rental.java
Table: rentals
Represents a rental transaction. Links to cars (carId) and customers (customerId). Also stores snapshot data (carName, plateNumber, customerName, customerPhone) so the rental record stays accurate even if the original data changes later.
entity/Payment.java
Table: payments | Extends: BaseEntity
Represents a payment made for a rental. Fields: rentalId (FK), amount, paymentDate, paymentMethod (CASH/CARD/MOBILE), status (PAID/PENDING/REFUNDED).
entity/Branch.java
Table: branches | Extends: BaseEntity
Represents a rental branch location. Fields: name, location, address, phone.

BACKEND - DTOs (Data Transfer Objects)

dto/CarDTO.java, CustomerDTO.java, PaymentDTO.java, BranchDTO.java, RentalDTO.java
Purpose: DTOs are containers that carry data between the frontend and backend. They have the same fields as their corresponding entities but without JPA annotations. This is a security best practice - you never send entity objects directly to the frontend.
OOP Concept: Encapsulation - all fields are private, accessed through getters and setters.

BACKEND - Repositories (Database Access)

repository/CarRepository.java, RentalRepository.java, CustomerRepository.java, PaymentRepository.java, BranchRepository.java
Purpose: These interfaces extend JpaRepository which provides ready-made database methods like findAll(), findById(), save(), deleteById(). Spring Data JPA automatically implements these methods - no SQL code needed.

BACKEND - Services (Business Logic)

service/*Service.java (interfaces) and service/impl/*ServiceImpl.java (implementations)
Purpose: Services contain the business logic of the application. They sit between controllers (which handle HTTP requests) and repositories (which handle database access).
Key methods in every ServiceImpl:
  • findAll(): Gets all records from DB, converts entities to DTOs using a for-each loop, returns the list.
  • findById(): Finds one record by ID or throws an error if not found.
  • save(): Converts DTO to entity, saves to database, converts back to DTO.
  • update(): Finds existing record, updates its fields, saves back.
  • delete(): Checks if record exists, then deletes it.
  • convertToDTO() / convertToEntity(): Helper methods that copy data between entities and DTOs field by field.
OOP Concept: Methods - each operation is a separate, named method that does one specific task.
service/impl/RentalServiceImpl.java (rentCar method)
Special logic: The rentCar() method does more than just save a record:
  1. Finds the car in the database.
  2. Checks if the car status is "Available". If not, it throws an error.
  3. Changes the car status to "Rented" so no one else can rent it.
  4. Creates a new rental record with the car details, customer info, dates, and cost.
  5. Saves the rental and returns the receipt data.
This demonstrates how business logic works in a real application.

BACKEND - Controllers (REST API Endpoints)

controller/CarController.java
Endpoints: GET /api/cars, GET /api/cars/{id}, POST /api/cars, PUT /api/cars/{id}, DELETE /api/cars/{id}
Purpose: Handles all HTTP requests related to cars. Each method corresponds to one CRUD operation.
controller/CustomerController.java
Endpoints: GET /api/customers, GET /api/customers/{id}, POST /api/customers, PUT /api/customers/{id}, DELETE /api/customers/{id}
Purpose: Handles all customer-related requests.
controller/RentalController.java
Endpoints: GET /api/rentals, GET /api/rentals/{id}, POST /api/rentals, PUT /api/rentals/{id}, DELETE /api/rentals/{id}
Purpose: Handles rental requests. The POST endpoint (rentCar) contains the special business logic for renting a car.
controller/PaymentController.java
Endpoints: GET /api/payments, GET /api/payments/{id}, POST /api/payments, PUT /api/payments/{id}, DELETE /api/payments/{id}
Purpose: Handles payment-related requests.
controller/BranchController.java
Endpoints: GET /api/branches, GET /api/branches/{id}, POST /api/branches, PUT /api/branches/{id}, DELETE /api/branches/{id}
Purpose: Handles branch-related requests.
exception/ResourceNotFoundException.java
Purpose: A custom exception class. When code tries to find a record that doesn't exist (e.g., car with ID 100), it throws this exception with a message like "Car not found with id: 100".
exception/GlobalExceptionHandler.java
Purpose: Catches all exceptions thrown by the application and returns proper HTTP error responses to the frontend. For example, if a car is not found, it returns a 404 status with an error message.

FRONTEND - React Files

frontend/package.json
Purpose: Lists frontend dependencies (React, ReactDOM, Axios) and scripts (npm start, npm run build).
frontend/.env
Purpose: Sets the frontend port to 3004 to avoid conflicts.
frontend/public/index.html
Purpose: The main HTML page. Contains a single <div id="root"> where React renders the entire application.
frontend/src/index.js
Purpose: The React entry point. It finds the "root" div and renders the App component inside it.
frontend/src/api.js
Purpose: Defines all API calls to the backend. Functions include findAllCars, saveCar, updateCar, deleteCar, rentCar, findAllCustomers, saveCustomer, etc. Each function uses Axios to make HTTP requests.
frontend/src/App.js
Purpose: The main application component. Features:
  • Navigation tabs: Cars, Rentals, Customers, Payments, Branches
  • Cars tab: Shows statistics (total, available, rented), search bar, car cards with Rent/Edit/Delete buttons
  • Rentals tab: Shows a list of all rental records
  • Customers, Payments, Branches tabs: Display the respective page components with full CRUD
components/CarForm.jsx
Purpose: A form to add a new car or edit an existing one. Fields: car name, plate number, brand (dropdown), model, year, price, status. Pre-fills fields when editing.
components/RentalForm.jsx
Purpose: A form for renting a car to a customer. Fields: customer name, phone, pickup date, return date. Automatically calculates rental days and total cost when dates are entered.
components/Receipt.jsx
Purpose: Shows a receipt popup after a successful rental. Displays receipt number, car details, customer info, rental period, and total cost. Has Print and Close buttons.
components/CustomerPage.jsx
Purpose: Full CRUD page for managing customers. Shows a list of customers with Edit/Delete buttons. Has a form to add/edit customers (first name, last name, email, phone, license number, address).
components/PaymentPage.jsx
Purpose: Full CRUD page for managing payments. Shows a list of payments with status badges. Has a form to add/edit payments (rental ID, amount, date, method, status).
components/BranchPage.jsx
Purpose: Full CRUD page for managing branches. Shows a list of branches with Edit/Delete buttons. Has a form to add/edit branches (name, location, address, phone).

DATABASE

9. Step-by-Step Guide: Running the Project in VS Code

Step 1: Set Up PostgreSQL Database

  1. Open pgAdmin or terminal.
  2. Create a database called carrental_db:
    CREATE DATABASE carrental_db;
  3. Make sure your PostgreSQL username is "postgres" and password is "postgres". If different, edit backend/src/main/resources/application.properties.
  4. (Optional) Run the database/schema.sql file to create tables manually, though Spring Boot will auto-create them.

Step 2: Open Project in VS Code

  1. Open VS Code.
  2. Click File > Open Folder.
  3. Select the project folder (the one with "backend", "frontend", "database" folders).
  4. Open two terminals: Terminal > New Terminal (do this twice).

Step 3: Start the Backend (Terminal 1)

  1. In Terminal 1: cd backend
  2. Run: .\mvnw spring-boot:run
  3. Wait until you see: Started CarRentalApplication in X seconds
  4. Do NOT close this terminal. The backend must keep running.
Note: The first run downloads many libraries. This may take a few minutes. Ensure PostgreSQL is running before starting the backend.

Step 4: Start the Frontend (Terminal 2)

  1. In Terminal 2: cd frontend
  2. Run: npm install (only needed the first time)
  3. Run: npm start
  4. Your browser will automatically open to http://localhost:3004

Step 5: Using the Application

The frontend has navigation tabs at the top:

Cars Tab

  • View all cars with their status (Available/Rented)
  • Click Add Rental Car to add a new car
  • Click Rent on an available car to open the rental form
  • Use Edit or Delete buttons to manage cars
  • Use the search bar to filter cars by name, brand, or plate

Rentals Tab

  • View all rental transactions with customer and car details

Customers Tab

  • View, add, edit, and delete customers
  • Fields: first name, last name, email, phone, license number, address

Payments Tab

  • View, add, edit, and delete payment records
  • Select payment method (Cash, Card, Mobile Money)
  • Set payment status (Paid, Pending, Refunded)

Branches Tab

  • View, add, edit, and delete branch locations
  • Fields: branch name, location, address, phone

Step 6: Stopping the Application

  • In each terminal, press Ctrl + C to stop the running process.
  • Or simply close VS Code.

10. Common Problems and Solutions

Problem: "java is not recognized"
Solution: Java JDK is not installed or not in PATH. Download Java 17, install it, and restart your computer.
Problem: "'node' is not recognized"
Solution: Node.js is not installed. Download Node.js 18+ and install it.
Problem: "Connection refused" or "Cannot connect to database"
Solution: PostgreSQL is not running. Start PostgreSQL service. On Windows: Search for "Services", find "postgresql", and click "Start". Also verify the database "carrental_db" exists.
Problem: "Port 8085 already in use"
Solution: Another program is using port 8085. Change the port in application.properties: server.port=8086. Also update the port in frontend/src/api.js.
Problem: "Failed to fetch cars. Is the server running?"
Solution: The backend is not running or the frontend cannot reach it. Make sure the backend terminal is still running. Check that api.js uses the correct backend URL (http://localhost:8085).
Problem: Maven build fails with download errors
Solution: Check your internet connection. Try running .\mvnw clean then .\mvnw spring-boot:run again.
Problem: "Database 'carrental_db' does not exist"
Solution: Create the database in PostgreSQL. Open pgAdmin or terminal and run: CREATE DATABASE carrental_db;
